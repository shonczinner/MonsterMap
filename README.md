# MonsterMap

Local tooling that builds a **monster table** (spawns, stats, drops) and an
**interactive single-file HTML map** of every monster spawn for the rs2b2t /
Lost City engine in this workspace. A second page renders that same monster data
as a filterable, sortable table.

`Server/` (engine, content, and webclient) is **untouched** — we only read from
it (source imports under a bundler / file paths). This folder has its own local
git repo.

## Pipeline

Three steps produce `out/monstermap.html`:

1. **`bun lib/maps/bake.ts`** — bakes terrain to PNGs. Runs the `Server/webclient`
   `MapView` headless (via `lib/maps/domShim.ts` + a `bun build` bundling step)
   once per map area, renders the whole area at 1 px/tile, trims the void/sea
   border, and emits:
   - `out/maps/surface.png`, `out/maps/dungeon.png`, `out/maps/extra.png`
   - `out/maps/layout.json` — per area: PNG size + world-tile → pixel mapping
 2. **`bun gen.ts`** — decodes spawn coordinates (`maps-server.zip`, binary),
    NPC/Loc/Obj configs (server/client caches), and content scripts (drop tables,
    skill resource tables) →
    - `out/data/monsters.tsv`, `out/data/monsters.json` — NPCs (fishing spots excluded)
    - `out/data/itemspawns.tsv`, `out/data/itemspawns.json` — ground-item spawns (`o{}`)
    - `out/data/resources.tsv`, `out/data/resources.json` — mining rocks, woodcut
      trees, flax, and fishing spots (`l{}` + `n{}` fishing spots)
    - `out/data/locationnames.tsv`, `out/data/locationnames.json` — city / area /
      POI labels (`content/maps/labels.txt`)
    - `out/data/minimapicons.tsv`, `out/data/minimapicons.json` — minimap icon
      legend + per-spawn POIs (locs with `mapfunction`, NPCs with `minimap`)

  4. **`bun list.ts`** — reads `out/data/monsters.tsv`, classifies each column as
     text or numeric, drops the `absX`/`absZ` spawn-coord columns, and writes a
     filterable **`out/monsters.html`** table (per-column substring + min/max
     range filters, sortable). Inlined JSON — no server needed.

  5. **`bun items.ts`** — loads the engine `ObjType` cache directly (read-only)
     and dumps every item's debug name, in-game name, stackable/members/notes,
     weight (grams), value, lendable/tradeable flags, and examine text to
     `out/data/items.tsv`, then renders a filterable **`out/items.html`** table
     with the same per-column substring + min/max range filters as the monster
     list. Ported from the standalone `ItemDebug/` folder so item data is
     generated in this repo.

  Or run **`bun build.ts`** to regenerate every page (map + list + items) at once.

Where `maps-server.zip` comes from: it's a **run-time artifact of the Server**,
generated by `engine/tools/pack/map/Pack.js` (`openArtifactStore('maps-server')`)
and cached at `$ENGINE_DIR/data/pack/.cache/maps-server.zip` (~15 MB). It is
gitignored in `Server/` and never committed anywhere; we only read it from that
path. It contains one entry per mapsquare `n{mapX}_{mapZ}` (483 files) holding
the NPC spawn coords (and land) used by `lib/tiles.ts`.
3. **`bun map.ts`** — reads the data + layout, stacks the three area PNGs
   **vertically** (no ocean gaps), plots every spawn dot, and writes
   `out/monstermap.html`. The page markup lives in `template.html`; the
   flash-matching / cluster logic in `lib/mapClustering.ts` is inlined into the
   page at build time.

## Usage

```bash
cd /home/shonc/rs2bot/MonsterMap
bun install          # fflate + playwright-core (smoke)
bun lib/maps/bake.ts # → out/maps/{surface,dungeon,extra}.png + layout.json
bun gen.ts           # → out/data/{monsters,itemspawns,resources}.{tsv,json}
bun build.ts         # → out/monstermap.html + out/monsters.html (all pages)
open out/monstermap.html
bun tools/smoke.ts   # headless Playwright check + screenshots
```

Individual pages can also be built on their own: `bun map.ts` and `bun list.ts`.

`lib/config.ts` reads `.env` (bun auto-loads it). Copy `.env.example` to `.env`
and set the base dirs; all derived paths are expanded from there. Optional CLI
flags override: `--engine/--content/--client/--out/--maps-server <dir|path>`.

## Map page controls

- **Areas** — checkboxes to show/hide each of surface / dungeon / extra.
- **Layers** — per-category toggles (Monsters / drops, NPCs / stores, Item
  spawns, Mining, Woodcut, Fishing spots, Map icons, Place names).
- **Find & flash** — type a name; the dropdown ranks exact → prefix → word-start
  → contains. Pick one and every matching dot **flashes in its layer colour**
  (other dots dim). Nearby matches collapse into one bigger disc labelled `xN`
  so clumps are easy to count.
- **Selection navigation** — a `‹ n / total ›` bar steps through the distinct
  matches; the `r` box sets the min tile spacing (default 32) used to collapse
  same-layer clumps for both the nav list and the flashing discs.
- **Min level** — slider hides monsters below a vislevel.
- **Hover** — tooltip with name, id, combat level, stats, area, tile, drops,
  and (for shops) stock.
- **Drag** to pan, **scroll** to zoom (pivots at the cursor).

## Monster list page controls (`out/monsters.html`)

A flat, filterable table of every monster (NPC) from `monsters.tsv`, linked from
the top nav bar.

- **Per-column filters** — text columns match by substring (same spirit as the
  map's name search); numeric columns have optional `min` / `max` inputs that
  filter by range ("between", either bound empty = open-ended). Filters combine
  with AND and re-run live on every keystroke.
- **Sortable columns** — click any header to sort asc/desc.
- **Result count** — `N / total` monsters shown.
- Spawn-coordinate columns (`absX`/`absZ`) are excluded — they're already plotted
  on the map and would just clutter the table.

Both pages share a top nav bar generated from `lib/pages.ts` — add a page there
and it appears in the bar on every page.

## Item list page controls (`out/items.html`)

A flat, filterable table of every item from the engine `ObjType` cache, linked
from the top nav bar. Same filter/sort UX as the monster list:

- Text columns (`debug`, `name`, `examine`) match by substring.
- Numeric columns (`id`, `noted`, `dummy`, `weight`, `value`) filter by optional
  `min`/`max` range.
- Boolean-ish columns (`stackable`, `members`, `lendable`, `tradeable`) are
  `yes`/`no` text, so filter by typing `yes`/`no`.
- Sortable headers; live `N / total` count.

## Layout

| File | Purpose |
|---|---|
| `.env` | Fully-expanded paths from `ENGINE_DIR` / `CONTENT_DIR` / `CLIENT_DIR` (gitignored). |
| `lib/config.ts` | Env + CLI-flag loader; expands `${VAR}` refs; validates required paths. |
| `lib/tiles.ts` | Unzips `maps-server.zip`, parses `n{mapX}_{mapZ}` spawn blocks. |
| `lib/drops.ts` | Drop-table parser (`[ai_queue3,…]` blocks, recursive `~proc` subtables, `npc_param(death_drop)`) + joiner to NPCs. |
| `lib/maps/bake.ts` | Bundles `bakeSource.ts` (`#/…` aliases rewritten to `Server/webclient`'s absolute source paths) and runs it with `JAG`/`OUT` env. |
| `lib/maps/bakeSource.ts` | Headless bake entry: `BakeMapView` (real `MapView` subclass) renders each area, crops, encodes PNGs + `layout.json`. |
| `lib/maps/domShim.ts` | Fake DOM/canvas for running the real game `MapView` under Node. |
| `gen.ts` | Spawns + configs + drops → out/data artifacts. |
| `build.ts` | Runs every page generator (map + list + items) to rebuild the whole site at once. |
| `map.ts` | Reads `template.html`, injects the data + `lib/mapClustering.ts` source, and writes `out/monstermap.html`. |
| `list.ts` | Reads `monsters.tsv`, inlines `{columns, rows}` JSON, and writes the filterable `out/monsters.html`. |
| `items.ts` | Loads engine `ObjType`, dumps `out/data/items.tsv`, and builds the filterable `out/items.html`. |
| `lib/pages.ts` | Single source of truth for the top nav bar (`PAGES` + `navHtml`). |
| `lib/listpage.ts` | Shared filterable-table builder used by `list.ts` and `items.ts`. |
| `template.html` | Page markup + CSS + inline browser script; `map.ts` fills in the data and clustering source. |
| `template_list.html` | List-page markup + CSS + inline filter/sort script (token-filled by `lib/listpage.ts`). |
| `lib/mapClustering.ts` | Flash-match + cluster de-duplication helpers (inlined into the page by `map.ts`). |
| `tools/smoke.ts` | Playwright smoke test: boots the page, exercises filters, area toggles, zoom; screenshots to `out/smoke*.png`. |

## Constraints

- **Server is untouched** — nothing is modified, added, or committed inside the
  `Server` repo. The bake reads `Server/webclient`'s client source read-only.
- **`out/`, `node_modules/`, `.env` are gitignored**; only source/docs are
  committed here.
- Dropped spawns: only dot spawns that fall inside a baked area's trimmed tile
  rectangle appear (~7.3k of 7.3k+; the rest sit in ocean/void tiles).
