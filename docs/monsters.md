# Monsters Tab

Where the monster/NPC data comes from, how it's generated, and how it feeds both
the map tooltip and the filterable `out/monsters.html` table.

## Output files

| File | Contents |
|------|----------|
| `out/data/monsters.tsv` | One row per spawn point (all NPC stats + combat bonuses + position) |
| `out/data/monsters.json` | Deduplicated per-NPC-id stats + combat bonuses (no drops) |
| `out/data/drops.json` | Kill loot per NPC id (item display names) |
| `out/data/stores.json` | Shop stock per NPC id (items the NPC sells) |
| `out/monsters.html` | Filterable/sortable table built from `monsters.tsv` |

## Source data

### Spawn coordinates — `maps-server.zip`

`lib/tiles.ts` unzips `maps-server.zip` (a runtime artifact of the engine,
generated by `engine/tools/pack/map/Pack.js` and cached at
`$ENGINE_DIR/data/pack/.cache/maps-server.zip`). It contains one entry per
mapsquare `n{mapX}_{mapZ}` holding NPC spawn coordinates. Each spawn has:
`(id, x, z, level)`.

`gen.ts` then may inject **phase-form** spawns (see `docs/drops.md`): bosses
whose loot NPC never appears in the zip (e.g. `kalphite_flyingqueen`) get a
clone of the base form's spawn, offset a few tiles, so both forms plot.

### NPC config — `NpcType` (engine binary cache)

Loaded in `gen.ts` from the engine's binary NPC config:

```ts
const { default: NpcType } = await import(...'NpcType.ts'...);
NpcType.load(dataPack);  // data/pack/server/npc.dat + client/config jag
```

`NpcType.get(id)` returns the NPC's base stats and properties:

| Field | Description |
|-------|-------------|
| `name` | Display name |
| `debugname` | Internal name (used for drop/script lookups) |
| `vislevel` | Combat level |
| `stats[]` | `[attack, defence, strength, hitpoints, ranged, magic]` — the 6 base combat stats |
| `members` | Members-only flag |
| `size` | NPC size (1 = standard) |
| `attackrange` | Melee attack range |

### Combat bonus params — `NpcType.params`

NPCs carry detailed combat bonuses as **params** (key-value pairs in the binary
cache). These are defined in the content source at
`Server/content/scripts/skill_combat/configs/npc_combat.param` and packed into
`npc.dat`.

| Param ID | Name | Notes |
|----------|------|-------|
| 101 | `stabattack` | Attack bonuses |
| 102 | `slashattack` | |
| 103 | `crushattack` | |
| 104 | `magicattack` | |
| 105 | `rangeattack` | |
| 106 | `stabdefence` | Defence bonuses |
| 107 | `slashdefence` | |
| 108 | `crushdefence` | |
| 109 | `magicdefence` | |
| 110 | `rangedefence` | |
| 111 | `strengthbonus` | Max hit modifier |
| 112 | `attackbonus` | General attack bonus |
| 116 | `attackrate` | Ticks between attacks (default: 4) |

`gen.ts` extracts these via `extractBonuses(type)` and includes them in every
monster record. NPCs without a param get `0` for base stats and `4` for
`attackrate` (the param-type default).

### Drop tables — `lib/drops.ts`

`DropResolver` reads content drop-table scripts (`.rs2` files under
`Server/content/scripts/drop tables/`) and `param=death_drop` lines from `.npc`
files. `dropsFor(debugname)` returns a flat `string[]` of item display names.

See `docs/drops.md` for the full pipeline, including the `randomjewel`
conditional (chaos vs nature talisman by area).

### Shop data — `lib/shops.ts`

`buildStores()` reads content `.npc` files for `param=owned_shop` and
`param=shop_title`/`shop_sell_multiplier`/`shop_buy_multiplier`/`shop_delta`,
joins with `.inv` stock files, and returns a map keyed by NPC debugname. See
`docs/stores.md`.

## Generation pipeline (`gen.ts`)

```
maps-server.zip  ──→  lib/tiles.ts  ──→  maps.spawns (id, x, z, level)
NpcType (npc.dat) ──→  NPC names, base stats, combat params
content scripts   ──→  lib/drops.ts  ──→  drop lists per NPC
content scripts   ──→  lib/shops.ts  ──→  shop data per NPC
                        │
                        ▼
                   gen.ts
                        │
          ┌─────────────┼─────────────┐
          ▼             ▼             ▼
  monsters.json   drops.json    stores.json
  (stats+bonuses)  (loot)       (shops)
          │
          ▼
  monsters.tsv (one row per spawn, all columns)
```

### TSV columns (`monsters.tsv`)

| Column | Source | Description |
|--------|--------|-------------|
| `absX`, `absZ` | `maps-server.zip` | Spawn tile coordinates |
| `level` | `maps-server.zip` | Spawn floor (0 = surface) |
| `id` | `maps-server.zip` | NPC config id |
| `name` | `NpcType.name` | Display name |
| `debug` | `NpcType.debugname` | Internal name |
| `vislevel` | `NpcType.vislevel` | Combat level |
| `att`, `def`, `str`, `hp`, `rng`, `mage` | `NpcType.stats[]` | Base combat stats |
| `members` | `NpcType.members` | Members-only |
| `size` | `NpcType.size` | NPC size |
| `attackrange` | `NpcType.attackrange` | Melee range |
| `stabatt` … `rngatt` | `NpcType.params` (101–105) | Attack bonuses |
| `stabdef` … `rngdef` | `NpcType.params` (106–110) | Defence bonuses |
| `strbonus`, `attbonus` | `NpcType.params` (111–112) | Strength/attack bonus |
| `attackrate` | `NpcType.params` (116, default 4) | Ticks between attacks |

### JSON structure (`monsters.json`)

```jsonc
{
  "generation": { "revisionTime": "...", "spawnRecords": 7994, "distinctIds": 1213, ... },
  "spawns": [ { "x": 2501, "z": 3247, "level": 0, "id": 9447 }, ... ],
  "monsters": {
    "9447": {
      "id": 9447,
      "name": "Steel dragon",
      "debug": "steel_dragon",
      "level": 246,
      "stats": [215, 215, 215, 210, 1, 100],
      "bonuses": { "stabdefence": 50, "slashdefence": 70, ... },
      "members": false,
      "size": 4,
      "attackrange": 10,
      "spawns": [ { "x": 2501, "z": 3247, "level": 0 }, ... ]
    }
  }
}
```

Drops and stores are separate files (`drops.json`, `stores.json`) merged at
render time by `map.ts`.

## How `map.ts` uses it

1. Loads `monsters.json`, `drops.json`, `stores.json`
2. For each spawn in `monsters.json.spawns`, looks up the NPC record by id
3. Attaches `point.drops` from `dropsData.drops[id]` (with per-spawn conditional
   resolution for the `randomjewel` talisman via `lib/conddrops.ts`)
4. Attaches `point.shop` from `storesData.stores[id]`
5. Attaches `point.bonuses` from the monster record's `bonuses` field
6. The hover tooltip (`template.html`) renders: name, level, combat bonuses
   (Att: X/X/X Magic:X Range:X Str:+X / Def: X/X/X Magic:X Range:X), drops,
   and shop stock

## How `list.ts` uses it

`list.ts` reads `monsters.tsv`, classifies each column as text or numeric,
drops the `absX`/`absZ` spawn-coordinate columns (already plotted on the map),
de-duplicates rows on content (so each monster appears once regardless of spawn
count), and builds `out/monsters.html` — a filterable/sortable table with all
remaining columns (including combat bonuses).
